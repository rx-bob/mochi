What the runtime did

No component-specific JavaScript. Ruby bytecode crosses one C ABI and one shared render buffer.

  1. Load bytecode

    Browser fetches my_counter.chi, restores the stripped RITE header, and loads the IREP into the singleton VM.

  2. Hydrate class

    C finds MyCounter, constructs the Ruby object, registers it, and the compiler-injected tag_name survives as Ruby code.

  3. Run mounted

    mochi_hydrate_component calls mounted. @mounted = 1 lands in component state before first paint.

  4. Apply css

    def css returns a string through the C buffer. It becomes one persistent <style> in an open shadow root.

  5. Render + click

    def html paints Count: 0. A shadow click writes an event line; C calls Ruby; the new HTML patches the same DOM.

Source → bytecode

The compiler only touches def html. CSS selectors keep their braces.
